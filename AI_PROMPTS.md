# AI Prompts — Книжковий магазин

## Інструмент і формат роботи

Використано AI-асистента OpenAI Codex.

Робота виконувалася в одній послідовній розмові. Нижче наведено дослівні уривки початкового повідомлення із завданням, згруповані за темами. Це частини одного запиту.

## 1. Code Review

> Виберіть 3 складних views/serializers з вашого проєкту
>
> Проведіть code review через ChatGPT/Claude
>
> Застосуйте рекомендації (якщо валідні)

Для ревью обрано:

- `catalog.views.checkout`;
- `catalog.views.checkout_success`;
- `catalog.async_views.book_list`.

Контекстом були вихідний код views, шаблон кошика та наявні тести. Оригінальний код, рекомендації, прийняті рішення й фінальний код наведено в `AI_REVIEW.md`.

## 2. Генерація тестів

> Згенеруйте тести для 2-3 моделей за допомогою AI
>
> Перевірте що тести проходять
>
> Досягніть coverage ≥ 60% для цих моделей
>
> Додайте коментар в кожному тесті:
>
> Generated with AI, reviewed and modified

Для цього пункту обрано моделі `Book`, `Order` та `OrderItem`.

AI враховував поля й методи моделей, наявні fixtures та фабрики. Нові тести моделей розміщено в `tests/test_ai_models.py`.

Додатково під час застосування рекомендацій ревью створено тести оформлення замовлення, збереження зміненого кошика та пагінації API.

## 3. Документація

> Згенеруйте docstrings для всіх views з AI
>
> Оновіть README з AI
>
> Додайте секцію "AI Usage" в README (які промпти використовували)

Для документування використано актуальний код:

- `accounts/views.py`;
- `catalog/views.py`;
- `catalog/async_views.py`.

README має описувати запуск проєкту, функціональність, тестування, coverage та використання AI.

## Уточнення під час роботи

Користувачка уточнила бажаний формат допомоги. Нижче наведено зміст цих повідомлень, а не дослівні цитати:

- пояснювати дії покроково;
- давати код і текст безпосередньо в чаті;
- описувати дії в PyCharm;
- давати повний вміст файлу, коли складно визначити місце вставлення.

До розмови також додавалися код, результати команд і повідомлення про помилки. Вони використовувалися як контекст для наступних кроків.

## Перевірка та відповідальність

AI пропонував зміни, тести й документацію. Авторка проєкту переносила зміни в PyCharm, запускала перевірки в Docker та передавала результати для аналізу.

Після перевірки рекомендацій змінювалися код і тести. Зокрема, перевірялися розташування тестових функцій, обробка помилок Stripe, збереження кошика та параметри пагінації.
